Is judging most of the job now?

2026-11-08

I bookmarked a rec from @BrettFromDJ:

"This thread is a literal goldmine for designers.

Highly recommend reading/bookmarking this."

The thread is by @VNallatamby, who used to work on Stitch and now works at Quest with their designer, @premiumtantan. Vincent wrote:

"Before Quest, I worked on Stitch and spent hours trying to understand how designers' jobs would evolve with AI.

Now I'm working with @premiumtantan every day on Quest, and I think we finally figured something out."

I'm not a product designer, and I haven't used Quest, so I'm not taking "we figured it out" as a verdict. What I cared about is the shape of the job he describes.

The work moved out of the old file

They still start in Figma. Vincent is clear about that: Tan used it "to set a first direction. Nothing new here." Once they liked the direction, Tan took those static visuals into Claude Code, turned them into components, and put the design system in a GitHub repository. After that, the underlying artifact is code.

That sounds a lot like what I wrote yesterday about a folder of markdown instead of a notes app. The familiar tool is how you start. The thing the agent can actually run is where the work lives.

The part that made me sit up is what fills the rest of the day. Vincent says Tan's main work now is "prompting, judging, iterating," and that this is "probably what takes 70% of Tan's time."

If that's true, the scarce skill isn't drawing the button. It's knowing which versions to keep.

They didn't skip the checking

This is not "the agent ships design now." Joel, their iOS engineer, added tests and structured the codebase so agent contributions have to clear a minimum quality bar. Tan's agent is connected to GitHub and has to follow their company rules. Vincent is explicit: "His contributions are reviewed both by agents and by humans. No auto-merge."

They also got Tan an iPhone 14 on purpose, so animations get checked on an older phone, not only on a Mac. And because design isn't a straight line — a new prompt usually overwrites the last version — they wrote a skill that keeps iterations as micro-branches, and dumps each one onto a shared canvas so people can go back and forth.

I wrote a few weeks ago about how much checking a change deserves, and about whether my agent should ask before it makes things safer. This team picked an answer I like: the agent can open the pull request. It cannot merge it. A test suite is the floor, not the finish.

There's a smaller trick I want to remember too. When Tan needs to nudge something tiny, like a corner radius, prompting is a bad tool and Figma would pull him back into the old file. So he asked Claude to build a configuration panel into the prototype, tuned the details there, then asked the agent to remove the panel. He stayed in the artifact instead of fleeing back to the app.

What I'd try

I'm not about to become an iOS designer. I do keep asking bots to write, change, and ship things for me. The honest parallel is: what would I need before I let one of them open a pull request?

Pick one small real surface I already care about. Put the source of truth in a repo the bot can edit. Write the shortest quality bar I would actually trust — a test, a checklist, something that fails out loud. Let the bot open a pull request. Do not auto-merge it. Spend a week only judging and sending it back.

If most of my time goes into judging, I'll know what the job became. If I keep ducking back into the old tool to fix details by hand, I'll know what I still need from it.
