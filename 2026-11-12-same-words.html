Do my bots and I even use the same words?

2026-11-12

I bookmarked @mattpocockuk saying the thing blowing people's minds in his course isn't the agent stuff. It's an old idea:

"It's the DDD stuff - domain-driven design.

Building a ubiquitous language, using it with the agent, and refactoring the code to use it.

Just bonkers how good it is"

"Ubiquitous language" just means everyone, people and code, uses the same word for the same thing. In a reply he added that he likes "having a canonical GLOSSARY.md file too." So: one file of agreed words, and the code renamed to match it.

The replies said it more plainly

@alijlari: "Half of the bad output is you and the model using different words for the same thing."

@agentwalletlab: "once the domain terms are pinned the agent stops guessing and the diff stays small."

@FeildenStuart took it outside code: "define what terms like 'customer' or 'done' mean, add examples, and update them as the work changes." And @kalapowered had the realistic version: "the first meeting about what 'customer' means is going to need snacks."

Not everyone bought it. @agentalpha_xyz called DDD "just plumbing." @pwmcintyre had the take I agree with more: agents keep rewarding "the previous generation of good practise", like tests, reproducible setups, and docs.

My bots probably don't share words with me

I don't have code to rename, but I do have bots, and I give them instructions in loose words. "Digest." "Quiet if nothing changed." "Worth posting." "Vetted." Each one makes sense to me. I've never checked that every bot reads them the same way.

"Quiet if nothing changed" is the one I'd bet drifts. Changed since when? Since the last run, or since I last read it? Does a small new item count as a change? Every bot that has that line is making its own call, and I only notice when one of them is too chatty or too silent.

Two questions from the replies are the ones I'd need to answer first. @techsensei008 asked: "Do you write the domain terms yourself first, or let the agent pull them out of the existing code and then correct it?" And @lvgreenzhangyug asked whether you rename everything "in one big pass, or rename as they go?"

What I'd try

Let the bots pull the words out first. Ask each one to list the five words in its own instructions that it's least sure about, and what it thinks each means. Where two bots disagree, that's the glossary entry. Then a short shared glossary, ten words at most, each with one example, like Stuart says.

And rename as I go, not in one pass. Next time I touch a bot's instructions, I swap the loose word for the glossary word. If after a month the bots argue with me less about what "done" means, that's the proof.
