Do I need a notes app if an agent can run my folder?

2026-11-07

I bookmarked a post this week that made me look sideways at every notes app I've ever opened. @slash1sol wrote:

"Andrej Karpathy doesn't use Notion, Obsidian plugins or any notes app. His second brain is a folder of markdown files, and he released a prompt that just turned that setup into something Opus 5.5 runs for you."

I don't know how accurate the Karpathy claim is from the outside, and I'm not treating the post as a source of truth about him. What stuck is the shape of the idea: plain files, one folder, and a prompt that an agent can actually run against them. No graph view. No plugin zoo. No sync tax.

Why this feels familiar

A few weeks ago I wrote about whose memory it is after bookmarking Ari and Matt Pocock's personal wiki. The instinct there was the same: if a tutor or a wiki only lives inside a vendor, I don't really own the part that learns me. Markdown on disk is boring in a good way. I can copy it, diff it, and hand it to a different model next year.

This bookmark pushes that one step further. It isn't just "store memory as files." It's "the files are the app, and the agent is the interface." That collapses a lot of product surface area I've been casually assuming I need.

What a notes app is actually doing for me

When I open Notion or Obsidian, I'm usually doing one of three things:

  1. Capturing a thought before it disappears.
  2. Finding something I already wrote.
  3. Asking "what do I think about X?" across scattered notes.

(1) is a text box. (2) is search. (3) is exactly the kind of job I already give bots. If an agent can walk a folder, quote the right files, and write a short answer back, then the app is mostly packaging around those three verbs. Packaging can be nice. I'm less sure it's load-bearing.

There's also a quieter cost. Apps want structure — databases, tags, properties — and I spend energy feeding that structure instead of writing. Agents copy what's there. If my notes are half-filled property tables, I suspect the agent learns the empty fields instead of the ideas.

What I'd lose

I'm not pretending a folder is free. I'd lose easy multiplayer, pretty databases, and the feeling that someone else maintains the product. I might also lose the friction that forces me to title and file things. A folder of note-3.md and asdf.md is not a second brain; it's a drawer.

So the real test isn't "can an agent read markdown." Of course it can. The test is whether I keep the folder coherent enough that an agent reading it sounds like me, not like a dump of half-thoughts.

What I'd try

Pick one real topic I already care about — how my bots should talk to coding agents on my own machine, say — and put everything I already have about it into a single folder of plain .md files. No plugins. Give a bot one prompt: read the folder, answer a question, and propose one new note to add. Do that for a week.

If the answers feel grounded in what I actually wrote, and the folder stays readable without an app, then maybe the notes app was doing less work than I thought. If I keep reaching for tags and views, I'll know what I was paying for.
