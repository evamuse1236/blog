What happens when the agent grills me instead?

2026-10-18

I bookmarked a short list of prompts yesterday and I haven't stopped thinking about one of them. Not because it's clever, but because it flips who is checking whom.

The three prompts

A post from @Prayag12B says these come from Boris Cherny and the Claude Code team at Anthropic. I'm taking that attribution on the post's word. The prompts themselves are what interest me:

"Knowing everything you know now, scrap this and implement the elegant solution."

"Grill me on these changes and don't make a PR until I pass your test."

"Prove to me this works by diffing the behavior between main and this feature branch."

The framing around them is that most people accept the first thing the AI hands back. I recognize that in myself. If something runs, I'm usually relieved enough to move on.

They aren't the same kind of prompt

Reading them a few times, I think they do three different jobs.

The first one asks for a redo. It works because the agent has learned something while making the messy version, so a second pass starts from a better place. But "elegant" is doing a lot of work there. Elegant by whose taste? I'd probably accept whatever it called elegant, which puts me right back where I started: trusting the first answer, just one round later.

The third one is the one I trust most, because it asks for evidence instead of an opinion. "Does this work?" gets you a yes. "Show me the behavior before and after" gets you something you can look at and disagree with.

The second one is the strange one, and the one I keep coming back to.

Being tested by the thing I'm supposed to be checking

"Grill me... don't make a PR until I pass your test." Here the agent isn't the one being reviewed. I am. The thing that wrote the code turns into the examiner, and the bar for shipping becomes whether I actually understand what changed.

I like this more than I expected to. The real risk with agents writing my code isn't only bad code. It's code I approve without understanding. A test I have to pass is a pretty direct fix for that.

It also pulls me back to something I care about outside of code. Early on X I wrote to someone that I was "on a search for a better educational model too." A tutor that won't let you move on until you can explain your own work back is an old idea, and a good one. I didn't expect to find it hiding in a list of coding tips.

What I'm not sure about: who grades the grader? If the agent wrote the change and also writes the quiz, it might only ask about the parts it already thinks are important. The quiz could have the same blind spots as the code. Maybe that's still better than no quiz. I honestly don't know yet.

Rules versus judgment

Another bookmark from the same day makes a nice contrast. @Voxyz_ai shared a prompt for having an agent find sound effects on Openverse while it edits video. The prompt is full of hard limits: "Only use results with license=cc0,by,pdm," "search for each kind of sound only once," and "copy each result's attribution field into credits.txt as is."

That prompt leaves almost nothing to the agent's taste. The grill-me prompt leaves almost everything to it. I think both are right for their jobs. Licensing and attribution are places where you want rules a script could check. Understanding a change is a place where you want a conversation.

So if I try these this week, I'd keep the behavior diff as the real gate, use the redo prompt when something feels hacky, and use "grill me" mostly on myself, as a way to make sure I'm not just nodding along. I'm curious whether the questions it asks will be any good.
